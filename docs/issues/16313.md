# Issue #16313 — (Locale): Missing Spanish text for Mountaineer Stormpike.
state: open, labels: Confirmed, 1-19, DB, Fix included, Good first issue, locale-esES/MX
summary: Mountaineer Stormpike (creature 1343) has no esES/esMX localized greeting text. Root cause per commenter trdillon's debugging: the creature carries the `UNIT_NPC_FLAG_GOSSIP` flag and `gossip_menu_id` 694, but `gossip_menu_option` has no row for menu 694 -- so the client renders the (missing) gossip text instead of falling through to `quest_greeting_locale`. Removing the gossip flag/menu makes the localized greeting display correctly.
status: applied
applied: sunstrider 2026-07-30, illidan 2026-07-30
verified-in-game: no
tables: creature_template, quest_greeting_locale
fix source: comment from trdillon (non-maintainer, but the SQL is fully concrete -- specific entry, specific column values, specific locale text) -- https://github.com/azerothcore/azerothcore-wotlk/issues/16313
sql applied:
```sql
UPDATE `creature_template` SET `gossip_menu_id` = '0', `npcflag` = '2' WHERE (`entry` = '1343');

INSERT INTO `quest_greeting_locale` (`ID`, `locale`, `Greeting`) VALUES (1343, 'esMX', '¡Bueno, bueno, si es un joven $c! Sin duda has venido porque has oído hablar de mis hazañas en el campo de batalla.$B$BPero no hay tiempo para historias ahora, ¡tenemos cosas muy importantes que hacer! Así que si lo que buscas es la gloria, la suerte te sonríe hoy...');
INSERT INTO `quest_greeting_locale` (`ID`, `locale`, `Greeting`) VALUES (1343, 'esES', '¡Bueno, bueno, si es un joven $c! Sin duda has venido porque has oído hablar de mis hazañas en el campo de batalla.$B$BPero no hay tiempo para historias ahora, ¡tenemos cosas muy importantes que hacer! Así que si lo que buscas es la gloria, la suerte te sonríe hoy...');
```
evidence: pre-apply SELECT on both `acore_world` and `acore_pb_world` matched the commenter's diagnosis exactly -- `creature_template` entry 1343 had `npcflag`=3, `gossip_menu_id`=694, and `gossip_menu_option` had zero rows for `MenuID`=694 (`gossip_menu` itself does have a row, TextID 1244, so the flag really was pointing at a dead end). `quest_greeting_locale` for ID 1343 had only a `deDE` row, no `esES`/`esMX`. Post-apply SELECT on both realms: `npcflag`=2, `gossip_menu_id`=0, and `quest_greeting_locale` now has deDE + esES + esMX rows for ID 1343; the esES text round-tripped through SSH/scp/mysql with the accented characters (¡, í, ó, ñ) intact, spot-checked with a raw SELECT.
