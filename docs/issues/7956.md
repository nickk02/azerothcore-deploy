state: open, labels: Confirmed, 30-39, DB, Fix included
summary: all Desolace hyena packs (Bonepaw Hyena 4688, Starving Bonepaw 4689, Rabid Bonepaw 4690) spawn stacked in place and never move, instead of patrolling per blizzlike wowhead sniff data. Duplicate of the still-open #5366.

verified-in-game: no
tables: creature, creature_formations, creature_addon, waypoint_data
fix source: comment from Grimfeather (CONTRIBUTOR) -- full DELETE+INSERT SQL for 6 hyena packs (30 creatures total), posted verbatim with a note that it was fixed for their own Individual Progression fork and "somebody else will have to make the PR" -- https://github.com/azerothcore/azerothcore-wotlk/issues/7956
schema adaptation: Grimfeather's SQL predates a `creature` table schema change -- current AC uses a single `id` column instead of the old `id1`/`id2`/`id3` difficulty-variant columns. Confirmed `id2`/`id3` were `0` on every one of the 30 rows in the original SQL (no difficulty variants involved), so the INSERT was mechanically rewritten to drop those two columns and keep `id1` as `id`. No position, orientation, waypoint, or flag values were changed -- this is a column-list translation, not a new fix. `creature_formations`, `creature_addon`, and `waypoint_data` inserts matched the current schema as-is (mysqld only ignored two harmless new columns not present in the original insert -- `velocity`/`smoothTransition` on `waypoint_data` -- which default to 0).
evidence: pre-apply SELECT on both `acore_world` and `acore_pb_world` confirmed all 30 target GUIDs (27939-27973) exist as entries 4688/4689/4690 with `MovementType`=0 or 1 and `currentwaypoint`=0 -- i.e. stacked and stationary, matching the bug report. No pre-existing rows in `creature_formations`/`creature_addon` for the 6 pack-leader GUIDs, and no `waypoint_data` rows for the 6 new path ids (279390/279490/279540/279590/279640/279690) -- clean apply, no collisions. Post-apply SELECT on both realms: all 30 creature rows recreated, all 6 leaders now `MovementType`=2 (waypoint-following) with `currentwaypoint`=1, 30 `creature_formations` rows (5 members per leader), 6 `creature_addon` rows, and waypoint_data point counts of 51/60/36/56/56/58 per path matching the row counts in Grimfeather's original SQL exactly.
